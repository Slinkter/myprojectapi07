# Proceso de Despliegue

> **Entorno actual**: GitHub Pages | **Build tool**: Vite | **Package manager**: pnpm

---

## 1. Configuración

El proyecto está configurado para GitHub Pages en `vite.config.js`:

```javascript
export default defineConfig({
  base: "/myprojectapi07",  // Base path para GitHub Pages
  // ...
});
```

### Scripts en `package.json`

```json
{
  "scripts": {
    "predeploy": "pnpm run build",
    "deploy": "gh-pages -d dist"
  }
}
```

- `predeploy`: Se ejecuta automáticamente antes de `deploy` → construye la app en `dist/`
- `deploy`: Sube el contenido de `dist/` a la rama `gh-pages`

---

## 2. Desplegar a GitHub Pages

```bash
# 1. Verificar que todo está limpio
pnpm lint          # 0 warnings
pnpm build         # 0 errores

# 2. Desplegar
pnpm deploy
```

El script:
1. Ejecuta `pnpm build` → genera `dist/` optimizado
2. Sube `dist/` a la rama `gh-pages`
3. GitHub Pages publica desde esa rama

**URL**: https://slinkter.github.io/myprojectapi07

> ⏱ Puede tardar 1-2 minutos en reflejar cambios.

---

## 3. Desplegar a otros hosting

El build en `dist/` es una app estática estándar. Funciona en cualquier hosting:

| Hosting | Método |
|---------|--------|
| **Netlify** | Conectar repo, build command: `pnpm build`, publish: `dist/` |
| **Vercel** | Conectar repo, build command: `pnpm build`, output: `dist/` |
| **AWS S3** | `aws s3 sync dist/ s3://bucket-name --delete` |
| **Nginx** | Copiar `dist/` al root del servidor |

### Importante para Vercel/Netlify

Cambiar en `vite.config.js`:
```javascript
base: "/",  // Quitar "/myprojectapi07"
```

Y cambiar a `createBrowserRouter` en `src/app/router/index.jsx`.

---

## 4. Rollback

### GitHub Pages
```bash
# Revertir último commit en gh-pages
git checkout gh-pages
git reset --hard HEAD~1
git push --force origin gh-pages
```

### Otros hosting
Cada servicio tiene su mecanismo. En Vercel/Netlify: redeploy desde el commit anterior en la UI.
