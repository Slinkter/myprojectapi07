# Visión General de Arquitectura

> **Stack**: React 18.3 + Vite 5.4 + Redux Toolkit 2.11 + Tailwind 3.4 + Motion 12
> **Arquitectura**: Feature-Sliced Design (FSD)

---

## 1. Feature-Sliced Design (FSD)

La app está organizada por **funcionalidades**, no por tipo de archivo. Todo lo relacionado con una feature vive en su carpeta.

```
src/
├── app/                    # Router (hash), layouts globales, error page
├── pages/                  # Composición de páginas
│   ├── PokedexPage.jsx     # Lista + búsqueda + favoritos
│   └── PokemonDetailPage.jsx # Detalle individual
├── features/               # Lógica de negocio encapsulada
│   ├── pokemon/            # state/, api/, hooks/, components/
│   ├── favorites/          # state/, hooks/, components/
│   ├── search/             # state/, hooks/, components/
│   └── theme/              # state/, hooks/, components/
├── entities/               # Modelos de dominio puros (sin state)
│   └── pokemon/            # types/, data/seed.js, model/ (mapper, utils)
├── shared/                 # Componentes y hooks reutilizables
│   ├── components/         # Pagination, layout/, GlobalErrorBoundary
│   └── hooks/              # usePagination, useLifecycleLog
├── store/                  # Configuración Redux (combina slices)
├── lib/                    # Utilidades (httpClient, logger, cn)
├── services/               # Configuración de API (base URL, endpoints)
└── utils/                  # Constantes (UI, TYPE_COLORS)
```

### Reglas de dependencia

```
app → pages → features → entities → shared
  └─────────────────────────────→ lib/services/utils
```

- **Features NO importan de pages**
- **Entities NO tienen Redux selectors** (son puras)
- **Shared NO conoce features**

## 2. Flujo de Datos Unidireccional

```
Usuario interactúa
      │
      ▼
Componente (JSX) dispatch action
      │
      ▼
Redux Thunk (async) → API call
      │
      ▼
Redux Slice actualiza estado
      │
      ▼
Selector memoizado calcula datos derivados
      │
      ▼
Componente re-renderiza con nuevos datos
```

## 3. Hash Router para GitHub Pages

**Problema**: GitHub Pages sirve archivos estáticos. `BrowserRouter` con URL `/myprojectapi07/pokemon/25` → el servidor busca el archivo `pokemon/25` → **404**.

**Solución**: `createHashRouter` → `https://slinkter.github.io/myprojectapi07/#/pokemon/25`
- El servidor solo ve `/myprojectapi07/` (existe)
- El hash `#/pokemon/25` lo maneja 100% JavaScript

### Rutas configuradas

| Path | Layout | Componente |
|------|--------|-----------|
| `/` | MainLayout (con Navbar) | PokedexPage (lazy) |
| `/pokemon/:id` | DetailLayout (sin Navbar) | PokemonDetailPage (lazy) |
| `*` | — | ErrorPage (404) |

## 4. Principios Arquitectónicos

| Principio | Descripción | Ejemplo |
|-----------|------------|---------|
| **Alta Cohesión** | Todo lo de una feature está junto | `features/pokemon/` tiene state, api, hooks, components |
| **Bajo Acoplamiento** | Features se comunican via interfaces claras | `usePokemon()` como API pública |
| **Separación de UI/Logic** | Componentes limpios, lógica en hooks | PokemonCard solo renderiza, usePokemonCard calcula |
| **Estado mínimo en Redux** | Solo lo global, lo local con useState | Tema, favoritos, pokemons en Redux; menú toggle con useState |
