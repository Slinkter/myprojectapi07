## 2. Redux: Store y Slices

### Store (`src/store/index.js`)

```javascript
configureStore({
  reducer: {
    pokemon: pokemonReducer,      // Datos + loading + error
    search: searchReducer,       // searchFilter string
    favorites: favoritesReducer, // Array de IDs
    theme: themeReducer,        // "light" | "dark"
  },
  middleware: (getDefault) =>
    getDefault({ serializableCheck: false }).concat(reduxLogger),
})
```

**`serializableCheck: false`**: Los objetos de Pokémon tienen referencias anidadas que el checker marca falsamente.

### Thunk → Slice → Selector

```
fetchPokemons({ page, limit })     ← dispatch desde usePokemon()
  → pending:   isLoading = true
  → fulfilled: pokemons = results, isLoading = false, totalCount = count
  → rejected:  isError = true, error = message

selectProcessedPokemons            ← createSelector (memoized)
  → map: añade favorite flag desde favoritesSlice
  → filter: aplica searchFilter desde searchSlice
  → retorna datos listos para UI
```

### Cuándo usar Redux vs useState

| Redux (global) | useState (local) |
|----------------|-----------------|
| Lista de Pokémon | Menú abierto/cerrado |
| Favoritos (IDs) | Valor de input temporal |
| Tema de la app | Estado de animación |
| Filtro de búsqueda | Tooltip visible |

**Regla**: Si 2+ componentes necesitan el dato → Redux.

## 3. Hash Router: Por qué

GitHub Pages sirve archivos estáticos. `BrowserRouter` usa la History API → intenta buscar `/myprojectapi07/pokemon/25` en el servidor → **404**.

`createHashRouter` → `/#/pokemon/25` → el servidor solo ve `/myprojectapi07/` → el hash lo maneja JS del cliente.

```javascript
createHashRouter([
  { element: <MainLayout />, children: [{ path: "/", element: <PokedexPage /> }] },
  { element: <DetailLayout />, children: [{ path: "pokemon/:id", element: <PokemonDetailPage /> }] },
  { path: "*", element: <ErrorPage /> },
])
```

**Lazy loading**: `lazy(() => import(...))` + `Suspense` → code splitting por ruta.

## 4. Custom Hooks como Fachada

| Hook | Responsabilidad |
|------|----------------|
| `usePokemon()` | Dispatch fetchPokemons + expone { pokemons, isLoading, isError, fetchPokemons } |
| `useFavorites()` | Toggle favorito + getFavoritePokemons (resuelve detalles vía API) |
| `useSearch()` | Set searchFilter en Redux slice |
| `useTheme()` | Toggle theme + detecta prefers-color-scheme del SO |
| `usePagination()` | Lee `page` de URL params + calcula totalPages + goToPage con scroll |

**Patrón Facade**: El componente no sabe de Redux. Solo llama al hook.

## 5. Sistema de Cache Híbrido

```
Prioridad de lectura:

1. memoryCache (Map, O(1), se pierde al cerrar navegador)
         ↓ miss
2. localStorage (JSON parse, sobrevive restart)
         ↓ miss
3. POKEMON_SEED (Map lookup O(1), 150 Pokémon hardcodeados)
         ↓ miss
4. HTTP GET a PokéAPI
```

**TTL**: 15 minutos. **Problema conocido**: memoryCache no tiene límite de tamaño (ver roadmap).

## 6. Optimizaciones de Performance

### React.memo
Todos los componentes de presentación usan `React.memo` con comparador custom cuando es necesario.

### Code Splitting (vite.config.js)
```javascript
manualChunks: {
  vendor: ['react', 'react-dom', 'react-router-dom'],
  redux: ['@reduxjs/toolkit', 'react-redux', 'redux-thunk'],
  pokemonSeed: ['@/entities/pokemon/data/seed'],
}
```

### Selectores Memoizados
`createSelector` de RTK → solo recalcula si las dependencias cambian.

### Big O Optimizaciones Aplicadas
- `.includes()` en loop → `Set.has()` O(1)
- `.find()` en cada render → Map lookup memoizado
- `.map()` + `.filter()` separados → chain único
