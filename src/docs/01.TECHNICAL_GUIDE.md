### 1.3 Decisión Arquitectónica: Hash Router para GitHub Pages

> **EL "PUENTE PEDAGÓGICO"**: ¿Por qué no usar `BrowserRouter` estándar?

GitHub Pages sirve archivos estáticos desde una ruta como `/myprojectapi07/`. Un `BrowserRouter` estándar usa la History API del navegador, que intenta cambiar la URL real del servidor. En un hosting estático, esto causa **404** porque:

1. Cuando el usuario navega a `/myprojectapi07/pokemon/25`, GitHub Pages busca un archivo called `pokemon`
2. Ese archivo no existe → 404 Error

**Solución**: `createHashRouter` usa el formato `#` (hash):
- URL real: `https://slinkter.github.io/myprojectapi07/#/pokemon/25`
- El navegador envía a GitHub Pages solo `/myprojectapi07/`, que sí existe
- El hash `#/pokemon/25` es manejado 100% por JavaScript del cliente

> **Analogía**: Es como dar instrucciones dentro de un edificio:
> - `BrowserRouter` → "Ve al edificio B, oficina 25" (el conserje no sabe dónde es)
> - `HashRouter` → "Busca el edificio A, luego pregunta en la oficina 25" (el hash guía dentro del mismo edificio)

## 2. Gestión de Estado con Redux Toolkit

### 2.1 Store Centralizado

**Archivo**: `src/store/index.js`

```javascript
const store = configureStore({
  reducer: {
    pokemon: pokemonReducer,      // Datos de Pokémon
    search: searchReducer,      // Filtro de búsqueda
    favorites: favoritesReducer, // Lista de favoritos (IDs)
    theme: themeReducer,        // Tema (light/dark)
  },
  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware({ serializableCheck: false })
      .concat(reduxLogger),
});
```

**¿Por qué `serializableCheck: false`?**
-redux toolkit verifica que el estado serializable (JSON-able). Our `pokemonSlice` storea objetos complejos de la API con formatos anidados. Deshabilitar esta verificación evita falsos positivos en desarrollo.

### 2.2 Async Thunk: fetchPokemons

**Archivo**: `src/features/pokemon/state/pokemonSlice.js`

```javascript
export const fetchPokemons = createAsyncThunk(
  "pokemon/fetchPokemons",
  async ({ page, limit }, { rejectWithValue }) => {
    const offset = (page - 1) * limit;
    const data = await pokemonApi.getPokemons(offset, limit);
    return data;
  }
);
```

**Flujo del Thunk**:
1. `pending`: `isLoading = true`, `isError = false`
2. `fulfilled`: `isLoading = false`, `pokemons = results`, `totalCount = count`
3. `rejected`: `isLoading = false`, `isError = true`, `error = message`

**Tabla de Interfaz del Estado**:

| Estado | Tipo | Descripción |
|--------|------|-------------|
| `pokemons` | `Array<Pokemon>` | Lista de Pokémon cargados |
| `isLoading` | `boolean` | True durante petición HTTP |
| `isError` | `boolean` | True si la petición falló |
| `error` | `string \| null` | Mensaje de error |
| `totalCount` | `number` | Total en la API (-1 inicial) |

## 4. Patrón Fachada en Custom Hooks

### 4.1 usePokemon (Facade)

**Propósito**: Abstraer la complejidad de Redux del componente.

**Archivo**: `src/features/pokemon/hooks/usePokemon.js`

```javascript
export const usePokemon = () => {
  const dispatch = useDispatch();
  const { pokemons, isLoading, isError, error, totalCount } = 
    useSelector((state) => state.pokemon);

  const fetchPokemons = useCallback(
    ({ page, limit = UI_CONSTANTS.POKEMON_GRID.ITEMS_PER_PAGE }) => {
      dispatch(fetchPokemonsThunk({ page, limit }));
    },
    [dispatch]
  );

  return { pokemons, isLoading, isError, error, totalCount, fetchPokemons };
};
```

**Tabla de Interfaz**:

| Propiedad | Tipo | Descripción |
|-----------|------|-------------|
| `pokemons` | `Array<object>` | Lista de Pokémon |
| `isLoading` | `boolean` | Estado de carga |
| `isError` | `boolean>` | Si hubo error |
| `error` | `string \| null` | Mensaje de error |
| `totalCount` | `number` | Total disponible |
| `fetchPokemons` | `function` | Función para cargar |

### 4.2 useFavorites (Facade + Resolución)

**Archivo**: `src/features/favorites/hooks/useFavorites.js`

```javascript
export const useFavorites = () => {
  const favoriteIds = useSelector((state) => state.favorites.favoriteIds);
  const dispatch = useDispatch();

  const togglePokemonFavorite = useCallback(
    (pokemonId) => dispatch(toggleFavorite(pokemonId)),
    [dispatch]
  );

  const getFavoritePokemons = useCallback(async () => {
    const detailPromises = favoriteIds.map((id) => 
      pokemonApi.getPokemonDetails(id)
    );
    return await Promise.all(detailPromises);
  }, [favoriteIds]);

  return { favoriteIds, togglePokemonFavorite, getFavoritePokemons };
};
```

**Patrón**: Este hook combina:
- **Selección** de IDs desde Redux
- **Dispatch** de acciones
- **Resolución** asíncrona de detalles usando la API

### 4.3 useTheme (Sistema + Persistencia)

**Archivo**: `src/features/theme/hooks/useTheme.js`

```javascript
export const useTheme = () => {
  const currentTheme = useSelector((state) => state.theme.currentTheme);
  const dispatch = useDispatch();

  useEffect(() => {
    const mediaQuery = window.matchMedia("(prefers-color-scheme: dark)");
    const handleChange = (e) => {
      if (!localStorage.getItem("app_theme")) {
        dispatch(setTheme(e.matches ? "dark" : "light"));
      }
    };
    mediaQuery.addEventListener("change", handleChange);
    return () => mediaQuery.removeEventListener("change", handleChange);
  }, [dispatch]);

  const toggleAppTheme = useCallback(() => dispatch(toggleTheme()), [dispatch]);

  return { currentTheme, toggleAppTheme };
};
```

**Detección del sistema operativo**: Si el usuario no ha elegido explíricamente un tema, se usa la preferencia del SO (`prefers-color-scheme`).

## 5. Sistema de Cache: Memoria + LocalStorage

### 5.1 Arquitectura de Cache (2 Niveles)

```
┌────────────────────────────────────────────────────────────────┐
│                    SISTEMA DE CACHE HÍBRIDO                     │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│   NIVEL 1: MEMORY CACHE (in-memory)                              │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │ const memoryCache = new Map()                           │  │
│   │ • Accesos O(1)                                         │  │
│   │ • Se pierde al cerrar el navegador                       │  │
│   │ • TL: 15 minutos                                      │  │
│   └─────────────────────────────────────────────────────────┘  │
│                              │                                  │
│                              ▼                                  │
│   NIVEL 2: LOCALSTORAGE (persistent)                          │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │ Clave: "pokemon_cache"                                 │  │
│   │ • Survive a restart del navegador                      │  │
│   │ • JSON con timestamp de expiración                     │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                │
│   FALLBACK: SEED DATA                                           │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │ POKEMON_SEED (150 Pokémon hardcodeados)                │  │
│   │ • Siempre disponible                                 │  │
│   │ • Sin dependencia de red                             │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

### 5.2 Lógica de Cacheo

**Archivo**: `src/features/pokemon/api/pokemonApi.js`

```javascript
const getCache = (key) => {
  // 1. Revisa memoria primero (más rápido)
  if (memoryCache.has(key)) return memoryCache.get(key);
  
  // 2. Revisa localStorage
  const storageCache = getCacheFromStorage();
  if (storageCache.has(key)) {
    memoryCache.set(key, storageCache.get(key)); // Promociona a memoria
    return storageCache.get(key);
  }
  
  return null; // No hay cache
};

const setCache = (key, data) => {
  memoryCache.set(key, data);
  const storageCache = getCacheFromStorage();
  storageCache.set(key, data);
  saveCacheToStorage(storageCache);
};
```

**TTL (Time To Live)**: 15 minutos (`1000 * 60 * 15`)

### 5.3 Prioridad de Lectura

```
1. memoryCache (instantáneo)
        ↓ (miss)
2. localStorage (parsing JSON)
        ↓ (miss)
3. SEED_DATA (búsqueda en Map)
        ↓ (miss)
4. HTTP request a PokéAPI
```

Este patrón garantiza:
- **Offline parcial**: Los primeros 150 Pokémon siempre disponibles
- **Velocidad**: consecutive loads son instantáneos
- **Persistencia**: Survives browser restart

## 7. Seed Data como Fallback

### 7.1 Por Qué Seed Data?

1. **Fallback offline**: API no disponible → datos locales
2. **Speed**: Sin latencia de red para los primeros 150
3. **Testing**: Datos consistentes y predecibles
4. **Cost**: Zero HTTP calls para los más populares

## 8. Optimizaciones de Performance

### 8.1 React.memo

Todos los componentes usan memoización:

```javascript
export default React.memo(PokemonCard, (prevProps, nextProps) => {
  return prevProps.pokemon.id === nextProps.pokemon.id;
});
```

**¿Por qué?**
- Evita re-renders innecesarios del hijo cuando el padre rerendea
- Crítico en listas de 20+ elementos

### 8.2 Code Splitting

**vite.config.js**:

```javascript
build: {
  rollupOptions: {
    output: {
      manualChunks: {
        vendor: ['react', 'react-dom', 'react-router-dom'],
        redux: ['@reduxjs/toolkit', 'react-redux', 'redux-thunk'],
        pokemonSeed: ['@/entities/pokemon/data/seed'],
      },
    },
  },
}
```

**Resultado**:
- `vendor.js`: ~170KB (React core)
- `redux.js`: ~50KB (state)
- `pokemonSeed.js`: ~200KB (seed data separado)

Carga paralela → mejor TTI (Time to Interactive).

### 8.3 Lazy Loading de Rutas

```javascript
const PokedexPage = lazy(() => import("@/pages/PokedexPage"));
```

Solo carga el chunk de la página cuando el usuario navega.

## Resumen: Decisiones Clave

| Decisión | Razón |
|----------|-------|
| Hash Router | GitHub Pages no soporta History API |
| Redux Toolkit | Estado complejo, múltiples features |
| Cache híbrido | Velocidad + persistencia + offline |
| Seed Data | Fallback offline, testing estable |
| React.memo | Listas largas = re-renders costosos |
| Lazy loading | Reducir bundle inicial |
