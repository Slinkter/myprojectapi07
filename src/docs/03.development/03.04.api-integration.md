# Integración con API

> **API**: PokéAPI (https://pokeapi.co/api/v2) | **Cliente**: Axios

---

## 1. Configuración

### `src/services/api/config.js`
```javascript
export const API_CONFIG = {
  BASE_URL: "https://pokeapi.co/api/v2",
  ENDPOINTS: { POKEMON: "/pokemon" },
  DEFAULT_PARAMS: { LIMIT: 20 },
};
```

### `src/lib/httpClient.js`
```javascript
const apiClient = axios.create({
  baseURL: API_CONFIG.BASE_URL,
  timeout: 10000,
});

// Interceptor de respuesta: logging estructurado
apiClient.interceptors.response.use(
  (response) => response,
  (error) => { /* logger.error + reject */ }
);
```

## 2. Servicio de Pokémon

### `src/features/pokemon/api/pokemonApi.js`

| Método | Descripción |
|--------|------------|
| `getPokemons(offset, limit)` | Lista paginada con detalles (fetch paralelo) |
| `getPokemonDetails(id)` | Detalle individual con cache |
| `transformPokemonData(data)` | Normaliza respuesta de API a formato interno |

### Cache Híbrido

```
Lectura:
1. memoryCache (Map, O(1))
2. localStorage (JSON parse)
3. POKEMON_SEED (Map, O(1))
4. HTTP GET

Escritura:
→ memoryCache.set() + localStorage persist (throttle 2s)
```

**TTL**: 15 minutos.

**Problema conocido**: localStorage se serializa en cada write sin throttle. Ver [`06.02.roadmap.md`](../06.maintenance/06.02.roadmap.md) §1.3.

## 3. Flujo completo

```
PokedexPage
  → usePokemon().fetchPokemons({ page, limit })
    → dispatch(fetchPokemons thunk)
      → pokemonApi.getPokemons(offset, limit)
        → cache check (memory → localStorage → seed)
        → si miss: HTTP GET
        → transformPokemonData(response)
      → return { results, count }
    → pokemonSlice.fulfilled → update state
  → selectProcessedPokemons → datos para UI
  → render PokemonList
```

## 4. Manejo de Errores

| Nivel | Mecanismo |
|-------|----------|
| HTTP Client | Interceptor → logger.error + reject |
| Servicio | try/catch → throw error |
| Thunk | rejectWithValue(error.message) |
| Componente | isError + error del state → UI de error |
